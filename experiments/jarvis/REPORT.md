## 优先修复方向

下一轮先在用户同意的本地离线模型上冻结一组多主题中文问题，加入改述、两字关键词、同名冲突、已纠错和无证据案例。逐题记录应召回的来源、实际前五、最终回答与耗时。先改造成漏召的部分，再看改善是否传到最终答案。对已投出但选错的案例单独处理阅读器。期间保留所有负对照和成本边界。

## 正式试用前复核

基线为 PR #148 的 eeeb5bd。此前四个格式失败文件在干净基线复现，独立格式提交对四个文件逐一比较 Python AST，全部相同。运行器信息、后续 CI 和阻塞以 PR 最新检查为准。初次加固在 Windows 两个版本都发现中文文件列表漏项；修复改用已打开文件句柄的链接数和属性。

在调优前固定 cases.tsv（SHA-256 由 evaluate.py 校验），同一组 10 条当前事实、1 条已遗忘旧事实及 1 条待审资料。40 个有来源问题、10 个无来源问题。当前评测作者拟定了标准答案，独立真人尚未逐题签核。该集参与开发诊断，不能视作独立留出集。逐题旧/新版候选 ID 及标准原文在 scores.tsv 中。旧版召回@5 为 21/40，新版 35/40，正例净增 14 道；有限词汇扩展与中文分词只对 Jarvis 开启。旧四问从 2/4 到 4/4。新版仍漏掉备用电源、两个阅读小组、宣传画初稿、声音训练等五个问法。两版均有 8/10 个无答案问题能检索到同主题候选；候选本身不构成答案。有些缺失属性、转述、时间冲突能通过确定性规则拦住，其余需要阅读器判断。

执行机在 127.0.0.1:1234 无服务，不能访问用户的 Windows 11 和 LM Studio。真实模型选证、实际正确率、无证据拒答率与引用有效率均未测。ModelCheck.cmd 只在确认本地推理后发送合成问题，保存每题的实际答案及候选。建议门槛分别为召回 85%、正例最终正确 90%、负例拒答 95%；在十道负例上需 10/10 才能达拒答门。更大独立样本仍有必要。

新增文件读取在 Windows 上固定父目录句柄，检查每个路径段的重解析属性，并从同一文件句柄读取。在 POSIX 上逐级使用只读目录描述符及 O_NOFOLLOW。拒绝链接、多硬链接、备用数据流和非授权类型。历史备份中的原文仍可能恢复。数据目录应由当前操作系统用户独占；本版的边界不包含同账号恶意进程篡改私有应用状态。取消测试、权限确认和文件内容作为资料展示见 FIRST-STEPS.txt。

local_check.py 使用临时中文空格目录，走实际控制台启动、退出和重启；Windows 走 Start.cmd。验证文件只读、junction/硬链接边界、损坏数据库中文诊断、重复启动、进程被终止时未提交的 SQLite 写入回滚、独立备份恢复、缺属性与冲突拒答；协议替身检查错误端口、断开连接、超时后恢复。这些结果不涵盖物理断电、Windows 11 真机或模型语义。启动包包括应用和 Stellamem 模块；需要本机 Python/Node，未捆绑运行时。

回滚代码可取 PR 的旧提交 eeeb5bd；数据可用先前备份的独立副本启动。新版默认使用新目录 Jarvis-Trial-V01，不迁移上版试用数据，不改生产配置。控制台没有文件整理写入、任意 Shell、手机遥控或对外发送能力。

第二轮 Windows 已通过全部 44 项基础断言，但从 Git 检出后用 cmd.exe 启动时遇到批处理换行解析错误。实验目录新增批处理 CRLF 检出规则。CI 改为按实际发布方式从 Git 快照构建 ZIP，逐项校验后解压到有中文和空格的路径，Windows 从包顶层 Check.cmd 开始验收。

另外使用真实控制台从外部驱动、在两次启动间隔开写入和读取，追加了调优未使用的 9 个查询：三个直接问法、三个两字提示、三个深度改述（轮椅剧场入口、借书归还、转接头）。旧版 3/9，新版 6/9。三个改述全部漏召。此结果未用于调整策略，提示本版仍无法保证泛化语义召回。
