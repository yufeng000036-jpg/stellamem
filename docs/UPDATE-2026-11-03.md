## PR #17：4 个治理功能（已合入 `c8d20307`）

借鉴来源：**记忆管家 V4.0.6**（社区 Skill，见 `docs/GOVERNANCE-4-FEATURES.md`）。

| 功能 | 之前什么样 | 现在什么样 | 区别在哪（好在哪） |
|---|---|---|---|
| F1 写前快照 + 一键回滚 | 写操作（索引重建、落库）前没有轻量保护，写坏了只能靠整树备份救 | 每次写操作前自动给 `index.db` + 关键配置拍文件级快照（SHA256 清单）；回滚要确认短语 `RESTORE`，恢复前先验 hash | 后悔药：轻量、自动、全程审计；且**不绕过 append-only**——快照只救运维事故，记忆修改仍走事务+过期 |
| F2 Token 看板 | 不知道记忆库多大、token 花多少，超预算靠感觉 | 只读看板：分组统计、token 估算（tiktoken 优先，否则 CJK 启发式并标注"估算"）、预算默认 30000、三色告警 | 原版有"超预算自动压实"，我们**刻意不做**：删除/压实必须人工复核，看板只给"建议复核清单" |
| F3 90 天时效衰减 | `rank.py` 里有遗忘曲线，但没接到 recall 上，等于摆设 | `recall(decay=True)` 按 base_score × retention 重排；只降排序，**不删条目、不改 status**；identity/core/pinned 永不衰减 | 旧记忆慢慢靠后站，但一条都不丢；顺手修了个真 bug：衰减在真实数据上曾静默失效（时间字段没认对） |
| F4 selector-audit | "写了这条记忆，但提问时想不起来"——查不出死在哪一层 | 9 个阶段逐层诊断：索引存在？namespace 放行？status？search 命中？min_score？去重？top-k？budget？decay？ | 只读诊断器，输出 verdict + 分阶段 JSON，修"想不起来"先有地方查 |

大白话：F1 是后悔药，F2 是体检表，F3 是"旧事先靠边但不扔"，F4 是"查案工具"。

## PR #18：MemSkill 轻量版（已合入 `19e7ec53`）

借鉴来源：**MemSkill 论文**（arXiv:2602.02474，"记法本身可以进化"；见 `docs/MEMSKILL-LITE.md`）。

| | 之前什么样 | 现在什么样 | 区别在哪（好在哪） |
|---|---|---|---|
| Skill Bank | "怎么记"是散落在各处的硬编码流程（pipeline、normalizer、security 各写各的） | 收敛成 **11 个**命名、版本化、带自然语言描述的 skill（INSERT/UPDATE/DELETE/SKIP 四原语 + 7 个领域 skill），规则选择，每次选用记审计 | "记法"从黑盒变成注册表：看得见、管得住、换得掉；**不用 RL 训练**，规则选择够用 |
| Designer 复盘 | 失败案例（没想起来/记错了）没人系统看 | `designer_review` 只读收集 hard cases，生成**pending 提案**；生效唯一路径：具名人类批准（确认短语 `APPLY`）→ 同一人应用 | 原版 Designer 会**自动进化**技能库；我们把自动进化砍了——**只许提议，不许自动改**，红线写死在代码里（模块里压根没有 `auto_evolve`） |

大白话：Skill Bank 是"记法的菜谱"，Designer 是"错题本"，但改菜谱的笔永远在人手里。

## PR #20：可读记忆两小件（已合入 `0ad18f58`，替代 #19）

来源：**Ant International《Text as a universal interface for transferable personalisation》**
（EMNLP 2026 获奖论文；见 `docs/READABLE-MEMORY.md`）。
Stellamem 本来就是文本记忆+审计链+人工批准，所以这次是**印证 + 补两小件**，不是路线大改。

| | 之前什么样 | 现在什么样 | 区别在哪（好在哪） |
|---|---|---|---|
| 桥规则 | 实践上过桥的都是提炼摘要（6 张常客卡），但没写成明文规矩 | ADR 0004："**过桥的永远是提炼摘要，原始日志永不过桥**" + 人工批准检查清单；`bridge.py` 加噪音提示器（只提示、不自动拒，真正边界永远是人看全文） | 把"一直在做的事"变成"写明的规矩"，新人/审计一眼看懂 |
| preference_summary | 没有"短、活、只讲偏好"的记忆类型，偏好只能挤在通用 claim 里 | 新一等 kind：`subject/text/evidence/updated_at/version/status`；**每条陈述强制带证据**，缺证据拒绝写入+记审计；支持更新（version+1）与撤回。pref-card-review 起新建/更新为 pending，具名批准后才 active，版本正文只追加 | 用户亲定的铁律写进校验："送小心心≠喜欢小心心特效"、"晚上来≠偏好晚上"——**证据只能支持证据本身**，想当然的推断写不进去 |

大白话：桥的规矩是"只传摘要不搬原文"；偏好卡是"每句话都要有出处"的活档案。

## PR #21：第二批 5 项（draft，未合入）

分支 `feat/batch2-beyond-20261103`。内容见 `docs/BATCH2-BEYOND.md`（该分支上）。
一句话版：

1. **Skill 运行时接线**——#18 时 skill 只是注册表；现在 `pipeline.py` 提取时真正按上下文选 skill，安全网默认带上，SkillBank 不可用时自动降级。
2. **偏好卡 recall 接线**——`recall()` 新增偏好卡/规律项通道（独立配额），注入标注 `[偏好]`/`[规律]` 并展示证据链；398 候选域与 namespace 规则不动。
3. **使用频率回流**——记录每条偏好卡被想起的次数与时间，只做信号；**模块里没有任何删除/降权路径**（测试显式断言过）。
4. **SenseNova 三件套**（行为启发，无代码）：主动提醒（只生成 pending 草稿，**模块内没有推送/发送方法**）、跨会话任务接续（纯函数简报）、冲突消解（双方证据并列，人裁决，**不自己改记忆**）。三项可独立关闭。
5. **睡眠巩固（文本版）**——定期把 episode 小结蒸馏成规律（带 provenance、可删）；规律项 recall 权重 ×0.8，低于原始记录。权重版（LoRA）明确不做。

## 刻意没做的（以及为什么）

| 没做 | 原因（一句话） |
|---|---|
| RL 训练闭环（MemSkill 原版） | 要训练 infra + 标注数据，投入产出比不划算；且自动进化与"人工拍板"冲突 |
| AlignXplore+ 两阶段训练（Ant） | 模型不开源，无代码可用 |
| 权重巩固 LoRA/MEMIT（Memo 论文原版） | 人格跑的是 API 模型（权重摸不着）+ 本地微调超预算 + 权重写入不可逆（与"能撤回"冲突） |
| 自动压实 / throttle（记忆管家有） | 删除与压实必须走人工复核，看板只给建议 |
| 忠实度自动判定（偏好卡证据"对不对"） | 经评估不可靠，模块只管"有没有证据"，对不对由人工评审 |

## 给非技术读者的一句话版

今天给 Stellamem 装了四样东西：**后悔药**（写前快照，写坏了能回滚）、
**体检表**（Token 看板，库多大一目了然）、**记法的菜谱**（Skill Bank，怎么记看得见管得住）、
**带出处的偏好卡**（每句话都要有证据）。另外立了两条规矩：
**过桥只传摘要不搬原文**，**机器只许提议、改不改人说了算**。
旧记忆不会静默消失，只会慢慢靠后站；删东西、改记法，永远要人点头。
