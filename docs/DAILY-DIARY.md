# 日档五段 + 长期“我变了什么”

## 这是什么

每天一份日档，五段是**触点 / 我的想 / 变 / 我的回 / 回声**；长期只记
**“我变了什么”**，只从真实变化里提炼。这是 Stellamem 最像人的那层：
白天发生的事先落在日档里，晚上 22:35 那步再从“变”一段里把真正的
变化提进长期。

按主体分开写：user 与 persona 各写各的日档、各有各的长期文件，
绝不共用、绝不串主体。个人侧先行，persona 侧用同一套代码、同一套
规矩。

## 文件

- 日档：`<root>/daily/<subject>/<YYYY-MM-DD>.md`
- 长期：`<root>/long-term/self-changes-<subject>.md`

```markdown
# 日档（user · 2026-11-06）

## 触点
- 晚上直播时钟丽潭点了《枫叶》

## 我的想
- 陪伴感比游戏操作更重要

## 变
- 决定以后开播先唱一首再聊

## 我的回
- 跟她说下次点歌直接报歌名就行

## 回声
- 弹幕说今晚的歌单很稳
```

长期文件每行自带来源：

```markdown
- 决定以后开播先唱一首再聊（规则合成·来源：2026-11-06 日档“变”）
```

## 两条硬规矩

### 1. 日档与长期都不进索引

索引器只抓扁平的 `daily/*.md`（`compiler/indexer.py` 的
`source_fingerprint` 与建库循环都是 `(root / "daily").glob("*.md")`，
不递归），MANAGED 清单里也没有 `long-term/self-changes-*.md`。
日档放在 `daily/<subject>/` 子目录里、长期文件不在 MANAGED 里，
所以两者都不会被召回——派生内容不与原文抢权重、不自我重复。
测试 `test_diary_files_do_not_change_index_fingerprint` 直接证明：
写日档、跑合成前后，源指纹一模一样。

### 2. 合成一律本地做，个人记忆不许出本机

v1 是**规则版**：摘录“变”一段 + 拼接进长期 + 标来源，不调任何模型，
更不调云端。DeepSeek 只跑过公开 benchmark 数据，绝不能用来写私人日记。
以后就算接本地模型，也只在 v1 的规则输出上做同一件事的升级，
合成行照样标明来源，云端模型永远不进这条链。

标记写实话：v1 的行标的是“规则合成”，不是“模型写”——因为它确实
不是模型写的。等哪天真上了本地模型合成，再改标记也不迟，
但“标明合成、标清来源日”这条永远不变。

## 22:35 那步

`synthesize_long_term()`（CLI `--synthesize`）：

- 当天没日档 → **什么都不做**，返回 noop，CLI 正常退出（exit 0），
  不建文件、不报错。没日记的那天本来就不该有长期变化。
- 日档在、但“变”一段为空 → 同样 noop。
- 有变化 → 只把没写过的行追加进长期文件；已写过的按原文去重，
  重复跑也不重复写（幂等）。

这步只读日档、不改日档；只写长期文件。日档的追加（白天）与合成
（晚上）写的是不同文件，不抢同一把锁。

## 写操作

一律原子写（`file_lock.atomic_write_text`：tmp + rename + 锁 +
fsync），崩溃不留半截文件。追加是单写者假设：每主体每天的日档
只由一条日间流程写。

## CLI

```bash
# 追加一行（五段之一）
python compiler/daily_diary.py --root <记忆根目录> --subject user \
  --date 2026-11-06 --append --segment 变 --text "决定以后开播先唱一首再聊"

# 看当日日档 / 看长期
python compiler/daily_diary.py --root <记忆根目录> --subject user --show
python compiler/daily_diary.py --root <记忆根目录> --subject user --long-term

# 22:35 那步（没日档时正常退出、什么都不做）
python compiler/daily_diary.py --root <记忆根目录> --subject user \
  --date 2026-11-06 --synthesize
```

`--date` 默认今天。主体写中文别名也认（`用户` → `user`），
未知主体、未知段、非法日期、空行、多行文本一律拒绝（exit 1，
不写文件）。

## 借鉴致谢

本功能的“日档五段 + 长期只记我变了什么”借鉴自外部记忆项目 v17
定稿的“日档五段 + 长期”一节（项目名与来源链接待补）：

- 采用了什么：每天一份日档、五段结构（触点 / 我的想 / 变 /
  我的回 / 回声）；长期只记“我变了什么”；当天没日记时晚间那步
  什么都不做。
- 为什么好：这是最像人的那层——白天是流水，晚上才沉淀出变化；
  长期只记变化，不把流水再抄一遍。
- 如何适配到 Stellamem：对方是单主体设计，Stellamem 按主体分开写
  （user 与 persona 各自的日档与长期，绝不共用）；对方的日档是
  普通文件，Stellamem 的日档与长期文件明确排除在索引之外（扁平
  `daily/*.md` 之外 + 不在 MANAGED 清单里），避免派生内容污染召回；
  对方的合成未注明实现方式，Stellamem v1 明确为本地规则版
  （摘录 + 拼接 + 标来源），个人记忆不许出本机，合成行标明来源日。
- 不抄的部分：对方没有主体隔离（见上）；本功能不做随机下沉/回流
  （遗忘必须显式、按条、可审计）。
