Stellamem

让 AI 的长期记忆像代码一样被编译、审查、版本化、回滚

Git-native · Auditable · Local-first Memory for AI Agents

作者 宇枫 · 2026

它解决什么问题

AI 助手越来越强，但它们的"记忆"却常常一团糟。

01

记忆腐烂

越积越乱，前后自相矛盾，久了连它自己都理不清。

02

记忆黑盒

数据库里到底存了什么，你看不到、也改不动。

03

说了记不住

聊过的重要事，转头就忘，反复重来。

04

乱记错记

一句气话被当成永久立场，错误被反复强化。

05

隐私外泄

记忆放在云端，你无法掌控它的去向。

它能干嘛

从"消化"到"注入"，一条完整的记忆生产链。

🧠

自动消化

日记 → 结构化记忆，拆成偏好 / 决策 / 教训 / 项目 / 身份。

🔀

智能路由

按类型去重、分派到对应文件，不乱堆。

⚖️

冲突治理

冲突日志 + 版本链，记忆可追溯、可还原。

🛡️

安全防护

防注入、防反话、防临时情绪，气话不会变成永久立场。

🔍

可解释可回滚

memory explain / history / rollback，每条记忆都有来处。

📊

量化评测

benchmark 有把尺子，改一次测一次，不靠感觉。

💉

自动注入

让 AI 一启动就"记得"——Adapter 把记忆喂回上下文。

📓

自动日记

聊完自动落盘，不漏一条。

🔒

本地优先

本地模型编译，隐私不出门。

怎么工作

一条单向管道，每一步都可查、可回退。

日记 / 对话
→
编译器（提取 + 判断）
→
结构化记忆（Markdown）
→
Adapter 注入
→
AI 读到
Markdown 是唯一真相，原文只保留在宿主会话中（Stellamem 只存指针与 hash）。

技术亮点

📄

白盒

一切记忆都是 Markdown，人能读、能改、能迁移。

🔌

框架无关

核心编译器不绑任何 AI 框架，OpenClaw 只是 Adapter #1。

⚙️

本地模型

Qwen3-4B 即可跑，可升级到更大模型。

📈

实测数据

单用户 30 篇日记：召回 0.705、精确率 0.505；对抗样本未观察到 False Write，不能外推为真实环境零错误。

愿景

"一个真实用户每天用 AI，连续 90 天、几千次交互后，
系统仍能准确回答：我现在相信什么、为什么相信、
以前相信什么、什么时候变的、依据是什么。"
核心信念：记忆属于用户，不属于某个 AI。
AI 可以换、模型可以换、框架可以换，
但 memories/ 还在那里。
