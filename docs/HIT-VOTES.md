# Hit 投票（2026-11-06）

召回真用上才算命中；投票只影响已获准召回内的排序，不删、不沉、不绕过任何门。

模块：`compiler/hit_votes.py`（计数器）+ `compiler/search.py` 的 `recall()`（加分与自动记票）
+ 接线：HTTP `POST /v1/vote` 与 MCP `stellamem_vote`（手动投票）、
夜间结算 `--votes`（报数）。持久化在 `<root>/system/hit-votes/votes.json`
（HTTP API）或 MCP 工作区的同名路径下；该目录不在索引指纹范围里，
记票本身不会让索引变旧。

## 规则

- **自动命中**：只有实际进入注入文本的记录才记一次。`recall()` 在 budget
  裁剪之后记；被 budget 截掉、没注入的不记。偏好卡/规律项仍走
  `UsageTracker`，不重复记。
- **手动投票只做补充**：只能投赞成票（+1），没有反对票、没有下沉票；
  手动票按半权计入排序加分，永远投不沉一条好记忆。
- **按主体分开计票**：key 写死成 `record:<标准主体>:<记录 id>`；persona
  的命中绝不抬高 user 的记录，反之亦然。未分类主体（自由文本旧 subject）
  不计票、不加分，失败关闭。投票目标必须存在，且投票主体与记录主体是
  同一命名空间，否则拒绝。
- **投票只排序**：加分只作用于已经通过 min_score、进入 top-k 的记录；
  没进候选池的记录投了票也不会被召回。加分 0.02 一个有效命中，封顶
  0.10，盖不过相关度本身。投票不绕过主体隔离、确认门、预算门、注入门。
- **只增信号，不碰内容**：没有任何删除 / 降权 / 自动清理路径，不提供
  delete / clear / reset。命中数是参考信号，不是质量判决；
  沉没与否的解读权在人，不在代码。
- **失败处理**：投票文件损坏时，召回路径从空开始（stderr 告警，不搞挂
  召回）；夜间结算用严格模式读，损坏时结算失败（非零退出，不写日志、
  不更新基线），不报不准的数。

## 手动投票入口

- MCP 工具 `stellamem_vote`：参数 `subject` + `record_id`（记录 id 或
  claim_id）。受宿主授权绑定约束（集外主体拒绝）；无索引库时无法校验
  目标，直接拒绝。
- HTTP `POST /v1/vote`：Master Token 才能调（受限 Token 只读）。参数同上；
  记录不存在报 404，主体不匹配报 403（不透露正文）。

## 夜间结算

结算 CLI 加 `--votes <投票文件路径>` 后，报告多一节“命中投票”：
今日 / 累计命中数（分主体，自动/手动分开）+ 命中最多的主体 × 类型
（仅主体 + 类型 + 次数，不含记录 id 与正文）。不给 `--votes` 或文件
不存在时，该节报“未启用”。

  沉没，数只报给人看；③按主体分开计票、投票只重排已获准召回内的记录，
  绝不绕过主体隔离与任何门
