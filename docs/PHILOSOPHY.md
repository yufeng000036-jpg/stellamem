# Philosophy

> Stellamem 的设计不是「怎么让 AI 记得更多」，
> 而是「AI 应该如何形成、更新、使用和遗忘记忆」。

---

## Memory is not a dump

聊天记录**不是**长期记忆。

原始对话里混着事实、情绪、玩笑、一次性猜测和自我保护性的措辞。
把整段对话塞回上下文，噪音会盖过信号。

长期记忆应该是**提炼结果**：
一条 Claim 说明「谁、在什么场景下、关于什么、持有什么立场」，并带上它凭什么被相信。

---

## Secret is not Memory

凭证永远不应该成为长期记忆。

API Key、Token、密码、Cookie、私钥 —— 它们的生命周期是「被使用」，不是「被记住」。
保留它们只会制造一个长期泄漏面。

所以 Stellamem 在任何模型调用**之前**就确定性识别并阻断密钥：
不写库、不进收件箱、不进日志、不进模型请求。

---

## Sensitive is not Auto-write

**值得保留 ≠ 自动允许写入。**

健康、身份、亲密关系、创伤这类内容，即使模型置信度很高，也只是「候选」。
它们进入人工复核收件箱，由**用户本人**决定是否成为长期记忆。

自动写入是便利，也可能是伤害。在敏感领域，我们选择后者不发生。

---

## Memory must have provenance

AI 应该知道「为什么相信这件事」。

每条 Claim 都带来源指针与内容 hash。
当来源无法解析（文件缺失、内容被改）时，Stellamem **报错，不编造**。

> 无来源的证据，比错误的来源更危险。

---

## Conflict must not disappear

冲突不能静默覆盖。

当新信息和旧记忆矛盾时，系统**不**默默用新的替换旧的：

- 无法确定是「更新」还是「冲突」时，进入 `UNCERTAIN`，不自动写；
- 判定为 `CONTRADICTS` 时，写入冲突日志，**双方证据都保留**；
- 判定为 `SUPERSEDES` 时，旧版本进入版本链，**可回滚**。

记忆的历史本身也是信息，不能因为「现在不需要」就抹掉。

---

## Users own their memory

用户应该能够：

- **看见** —— 每条记忆都是可读的 Markdown
- **修改** —— 直接编辑或通过收件箱 `edit`
- **拒绝** —— `reject`，候选不进入 canonical memory
- **删除** —— 由用户决定，系统不擅自清理
- **回滚** —— 事务可恢复，版本链可追溯
- **导出** —— 纯文本 / Markdown，不被格式锁定

AI 的记忆属于用户，而不是反过来。

---

## 关于「遗忘」

遗忘不是删除。

长期运行的系统需要区分：

- **过时** —— 事实变了（`SUPERSEDES`）
- **冲突** —— 两条都可能是真的（`CONTRADICTS`）
- **临时** —— 当时的情绪，不是持久的立场（`temporary`）
- **敏感** —— 需要人工判断是否该长期保留

把「遗忘」当成一个**可治理的决策**，而不是一次不可见的覆盖。

---

## 一句话

> **Memory should be inspectable infrastructure, not invisible magic.**
